# 시연 순서 (영상 100초 안팎)

왼쪽에 에뮬레이터, 오른쪽에 가상 콘솔 브라우저 탭을 한 화면에 놓고 녹화한다. **소리가 반드시 들어가야 한다.** 가수 목소리가 줄고 돌아오는 것이 이 앱의 전부다.

## 준비

```bash
~/Android/emulator/emulator -avd Pleos_Connect_v2.1 -no-snapshot -no-boot-anim -gpu host &
adb wait-for-device
adb forward tcp:8088 tcp:8088
adb install -r apk/Graphite_Sichimi_release.apk
adb shell pm clear --user 10 app.sichimi          # 기록을 비우고 시작(오늘 요약·내 기록을 깨끗하게)
```

- 브라우저로 `http://127.0.0.1:8088/`을 열고 아래에 **DDS ONLINE**이 뜨는지 본다(탭을 닫으면 OFFLINE이 된다).
- 에뮬레이터를 켠 직후에는 내비가 1~2분 늦게 답할 수 있다. 장면 7 전에 내비를 한 번 열어 둔다.
- 콘솔 시작 상태: 운전석 착석, 동승석·뒷좌석 비어 있음, 문 넷 닫힘, 창문 넷 0%, 방향지시등 끔, 기어 P.
  - 같은 상태를 명령으로 만들려면: `python3 tools/console.py seat driver on`, `seat passenger off`, `door front_right close`, `window front_left 0`, `turn off`, `gear P` 등.
- 앱을 연다: 런처의 「시치미」 또는 `adb shell am start --user 10 -n app.sichimi/.MainActivity`.
- 음량: 호스트 스피커 음량을 녹음에서 찌그러지지 않을 만큼(70% 안팎)으로.

## 장면

| # | 시간 | 콘솔에서 할 일 | 앱에서 할 일 | 보이고 들리는 것 | 자막(선택) |
|---|---|---|---|---|---|
| 1 | 0:00~0:22 | **기어 D** | 재생(첫 곡이 한국어 곡이다) | 5초 동안 평범한 재생. 그 뒤 가수 목소리가 작아지고 「혼자만의 노래방」. 재생 15초쯤 **딸깍 네 번**(박자 세기) 뒤 16.6초에 첫 소절이 작은 가이드 목소리로 나온다 | 혼자, 문·창문 닫힘 → 5초 뒤 노래방. 첫 소절 앞 박자 세기 |

| 8 | 1:29~1:42 | 내비 **안내 종료** → 앱으로 돌아와 **기어 P** | 오늘 요약 보기 → **내 기록** 탭 | "오늘 n곡, 혼자 부른 시간 …, 들킬 뻔한 순간 n번(가장 빠른 대피 0.2x초)", 이번 달 기록과 비밀 차트 | 오늘 몰래 부른 기록 |

- 장면 1~5와 8이 핵심이다. 6·7은 시간이 모자라면 뺀다.
- 장면 2의 문은 첫 소절이 나온 뒤에 연다. 아리랑은 16.6초까지 반주만 있어서, 그 전에 열면 가수 목소리가 돌아오는 것이 들리지 않는다. 문을 일찍 열면 박자 세기 딸깍도 함께 빠진다(노래방일 때만 들린다).
- 박자 세기는 설정 탭 「첫 소절 박자 세기」로 끄고 켠다(기본 켬). 시연 전에 켜져 있는지 본다.
- 장면 6을 하려면 장면 5 끝에 노래방 상태여야 한다(창문을 닫고 8초 기다린다).
- 장면 7은 장면 6 뒤 노래방 상태에서 한다. 녹화 전에 한 번 연습으로 목적지를 넣어 두면 "최근" 목록에 올라와 빨리 고를 수 있다(연습 뒤 안내 종료). 내비 화면이 꼬이면 `adb shell am force-stop --user 10 ai.umos.maps.android.navigation.app` 뒤 다시 연다. 목적지를 넣고 경로가 시작된 뒤 앱이 남은 시간을 받기까지 2~6초 걸린다. 앱이 **재생 중**이어야 내비 이벤트를 받는다.
- 장면 8의 오늘 요약은 마지막 주행(장면 4에서 D로 바꾼 때부터)만 센다. 내 기록은 이번 달 전체다.
- 모든 장면은 콘솔 신호로만 움직인다. 앱 안에 가짜 신호 버튼은 없다.

## 소리까지 담는 녹화

에뮬레이터 소리는 PipeWire를 거쳐 호스트 스피커로 나온다. 호스트 화면 녹화가 시스템 소리를 함께 담아야 한다.

**가. OBS Studio(무료, 추천)** — 한 파일에 화면과 소리가 같이 담긴다.

1. `sudo apt install obs-studio` (설치는 직접 한다).
2. 소스: "화면 캡처(PipeWire)" 하나, "오디오 출력 캡처(PulseAudio)"에서 기본 출력 장치 하나.
3. 설정 → 출력: 녹화 형식 mp4(또는 mkv 뒤 remux), 1920x1080, 30fps.
4. 녹화 시작 → 위 장면 → 녹화 중지.

**나. GNOME 화면 녹화 + 따로 녹음 + 합치기** — 설치 없이 된다. GNOME 기본 녹화(Ctrl+Shift+Alt+R 또는 스크린샷 메뉴의 녹화)는 소리를 담지 않으므로 소리를 따로 받아 합친다.

```bash
# 1) 녹음 시작(장면이 끝나면 Ctrl+C)
parecord --format=s16le --rate=48000 --channels=2 --device=@DEFAULT_MONITOR@ recordings/audio.wav
# 2) 바로 GNOME 화면 녹화 시작 → 장면 → 녹화 중지(~/비디오/Screencasts/*.webm)
# 3) 맞추기: 장면 1에서 재생을 누른 순간(화면에서 버튼이 바뀐 프레임)과 소리가 시작된 순간의 차이를 재서 OFFSET(초)에 넣는다.
ffmpeg -i ~/비디오/Screencasts/화면.webm -itsoffset -OFFSET -i recordings/audio.wav \
       -map 0:v -map 1:a -c:v libx264 -crf 20 -c:a aac -b:a 192k -shortest recordings/sichimi_demo.mp4
```

- `recordings/`는 저장소에 넣지 않는다(.gitignore).
- 녹음이 되는지 먼저 5초만 받아 확인한다: `parecord ... recordings/test.wav` 뒤 `paplay recordings/test.wav`.
- 에뮬레이터 소리 경로는 신호에서 호스트 스피커까지 약 0.4초다(앱 출력까지 약 0.25초 + 에뮬레이터 전달 약 0.15초, 검증기록 G2). 영상에서 문을 연 순간과 소리가 바뀐 순간 사이에 그만큼 틈이 보일 수 있다.

