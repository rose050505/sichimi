# 녹화 방법 (개발용)

시연 영상 세 편을 찍고 합친 방법이다. 장면별 조작과 시각은 [시연순서.md](시연순서.md)에 있다. 녹화 원본(`recordings/`)은 저장소에 넣지 않는다.

## 노래 점수 영상(사람이 직접 부름)

본 영상과 따로 찍었다(`docs/media/demo_score.mp4`).

| 할 일 | 보이고 들리는 것 | 자막(안) |
|---|---|---|
| 기어 D, 혼자에서 한 곡을 **직접** 끝까지 부른다(이어폰을 끼면 스피커 소리가 마이크로 다시 들어가지 않아 점수가 정확하다) → 기어 P → 「점수」 탭 | 곡이 끝나면 음성 "○○, n점. 첫 기록이에요". 점수 탭에 방금 점수, 지난번의 나와 대결, 곡별 최고 | 혼자 부르면 점수 — 지난번의 나와 대결 |

**찍는 순서(11/14, 녹화 도구가 거의 다 한다)**

1. 에뮬레이터·콘솔 하트비트를 [시연순서.md](시연순서.md)의 「직접 해 보기(준비)」대로 띄운다. 다른 무거운 프로그램은 닫는다(소리 끊김).
2. 이어폰을 끼고, PC 소리 설정에서 **출력 = 이어폰**, **입력 = 쓸 마이크**를 고른다. 반주가 들리게 출력 음량을 올린다(녹화는 qemu 출력을 바로 받아 호스트 음량과 상관없다).
   블루투스 이어폰이면 입력은 노트북 내장 마이크로 둔다(이어폰 마이크를 고르면 통화 음질로 바뀌어 반주가 뭉개진다). 이어폰을 끼면 내장 마이크로 반주가 새지 않는다.
3. 명령 한 줄(곡을 바꾸려면 끝의 곡 id만 바꾼다: `03-wade` 3분 5초, `01-arirang` 3분 21초, `02-destroy` 3분 48초):

```bash
python3 tools/record_demo.py score recordings/demo_score 03-wade
```

   도구가 하는 일: 설정 「노래 점수(마이크)」 켬(처음이면 권한 창 「앱 사용 중에만 허용」을 누름), 「전국 랭킹에 올리기」 끔, qemu 마이크 입력을 호스트 기본 입력으로 옮김(시험용 `sichimi_mic`에 가 있어도 되돌림), `adb emu avd hostmicon`, 주차·혼자에서 곡을 틀어 노래방이 되면 일시정지, 기어 D.
   터미널에 듣는 곳·마이크·**마이크 2초 크기**가 찍힌다. −75dBFS보다 작다고 나오면 마이크가 꺼졌거나 음소거다(Ctrl+C로 끄고 소리 설정을 본다).
4. 준비되면 **Enter** → 곡이 처음부터 나온다. 주행 화면에는 가사가 없어 **터미널에 가사가 한 줄씩**(들리기 0.6초 전) 뜬다. 끝까지 부른다(곡 음표의 절반 넘게 마이크가 들어야 완주로 쳐서 점수 음성이 나온다. 부르지 않는 구간도 마이크가 켜져 있으면 센다).
5. 곡이 끝나면 알아서: 점수 음성 「○○, n점. 첫 기록이에요」 → 기어 P → 점수 카드 → 「점수」 탭 → 멈춤 → 합치기. 결과 **`docs/media/demo_score.mp4`**(약 45초: 노래 시작 15초 + 곡 끝 13초 전부터 점수 탭까지. 그 사이는 잘라 내고 「(2분 뒤)」 자막).
6. 터미널 끝에서 확인: `점수 곡 끝: … 완주=true`, `목소리:` 줄의 `lag_used_s`(목소리를 당긴 값)와 `env_corr`(0.2보다 크면 잰 값을 씀). 영상을 들어 목소리가 반주에 맞는지 본다. 어긋나거나 크기가 마음에 안 들면 녹화는 그대로 두고 합치기만 다시 한다:

```bash
~/.venvs/demucs/bin/python -I tools/compose_demo.py recordings/demo_score docs/media/demo_score.mp4 --mic --mic-lag=0.25 --mic-db=3
```

- **확정본(11/14)**: 아리랑, 블루투스 이어폰 + 내장 마이크, **54점 완주**, `docs/media/demo_score.mp4` 56.7초(목소리 반주 +5dB, 커밋 0a13447).
- 다시 찍으려면 폴더 이름만 바꾼다(`recordings/demo_score2`). 그만두려면 Ctrl+C(담은 것은 남기고 영상은 만들지 않는다).
- 목소리 맞추기: 부르는 사람은 이어폰에서 들리는 반주에 맞춰 부른다. 영상의 화면은 소리보다 약 0.45초 빠르므로(에뮬레이터 출력 지연) 목소리는 화면이 아니라 녹음 속 반주에 맞춘다. 두 녹음을 호스트 시계로 겹친 뒤 남는 틈(이어폰·마이크 지연)은 목소리와 원곡 보컬의 크기 굴곡을 맞대어 잰다. 크기는 노래 구간에서 반주보다 1dB 크게, 곡 처음·끝과 조각 앞뒤에서 0.5초 페이드.
- 점수는 직접 부른 것만 쓴다(시험 도구가 원곡 보컬을 넣어 만든 점수는 쓰지 않는다). 11/14 시험이 Wade에 「57점, 완주 아님」 한 줄을 남겼다. 완주가 아니라 최고 기록·「첫 기록」 판단에는 들어가지 않지만, 점수 탭의 곡별 목록에 「최근 57점 · 1번」으로 보이고 Wade를 부르면 「2번 불렀어요」가 된다.
- 「전국 랭킹에 올리기」는 끈 채로 둔다(서버에 기록이 생기지 않는다). 점수 탭의 전국 랭킹 칸은 서버에서 읽기만 한다.


## 본 영상·가사 싱크 녹화(자동)

Wayland라 셸에서 데스크톱을 녹화할 수 없어 화면·소리·콘솔 탭을 따로 담고 합친다.

```bash
python3 tools/console.py heartbeat &                                   # DDS ONLINE 유지
python3 tools/record_demo.py test recordings/demo_test                 # 20초 시험 녹화: 소리가 들어가는지, 화면과 맞는지
~/.venvs/demucs/bin/python -I tools/compose_demo.py recordings/demo_test recordings/demo_test/test.mp4
python3 tools/record_demo.py main recordings/demo_main6                # 본 녹화(미리 돌리기 포함 약 8분, 이 대본 그대로)
~/.venvs/demucs/bin/python -I tools/compose_demo.py recordings/demo_main6 docs/media/demo_main.mp4
python3 tools/record_demo.py lyrics recordings/demo_lyrics             # 가사 싱크(아리랑 처음부터 58초)
~/.venvs/demucs/bin/python -I tools/compose_demo.py recordings/demo_lyrics docs/media/demo_lyrics_sync.mp4 --layout=lyrics
~/.venvs/demucs/bin/python -I tools/check_lyrics_sync.py recordings/demo_lyrics 01-arirang
python3 tools/record_demo.py score recordings/demo_score 03-wade            # 노래 점수: 사람이 부른다(위 「노래 점수 영상」), 합치기까지 함
python3 tools/record_demo.py score recordings/score_test 03-wade --test 32  # 사람 없이 시험(가상 마이크에 원곡 보컬, 점수 한 줄이 남는다)
python3 tools/record_demo.py score recordings/score_full 03-wade --test full --voice none   # 곡 끝까지 흐름만(점수는 안 남음, 곡 기록은 남음)
```

- 에뮬레이터 화면: `adb shell screenrecord`(본 녹화 1280x720 6Mbps, 가사 1920x1080. 한 조각 180초까지라 ⑧ 뒤에서 조각을 나눔).
- **소리 끊김 막기(11/14):** screenrecord는 에뮬레이터 안 소프트웨어 인코더라 CPU를 많이 먹는다. 1080p로 찍은 첫 영상은 후진(후방 카메라 앱이 같이 뜸)과 첫 내비 안내 음성 때 호스트 CPU가 모자라 qemu 소리가 끊겼다. 그래서 본 녹화는 크기를 줄이고(합칠 때 1440x810으로 줄이므로 손해 없음), 콘솔 탭을 `nice 10`·프레임 절반으로 띄우고, 녹화 전에 내비 길 안내와 TTS를 한 번 돌려 둔다(`record_demo.py`가 알아서 함). 그래도 후진 순간 남는 수 ms\~수십 ms 무음 틈은 `compose_demo.py`가 바로 앞 소리로 메운다(`--keep-gaps`로 끔). 녹화하는 동안 다른 무거운 프로그램은 띄우지 않는다. 호스트에서 녹화하는 `adb emu screenrecord`는 소리가 더 끊겨서 쓰지 않는다.
- 소리: `parecord --monitor-stream=<qemu 스트림 번호>`. qemu 출력만 디지털로 받으므로 호스트 스피커가 음소거여도 담기고, 방 소리·다른 프로그램 소리가 섞이지 않는다(마이크를 쓰지 않음). 차 음량이 기본값(-25dB)이라 작게 담겨 합칠 때 키운다(약 +21dB, 최고 −1dB 아래).
- 콘솔 탭: `tools/console_tab.js`가 8088 페이지를 헤드리스 크로미움으로 열어 프레임을 받고 버튼을 실제로 누른다(playwright 위치는 환경 변수 `PLAYWRIGHT`로 정함).
- 맞추기: 소리와 콘솔 프레임은 호스트 시계. 화면 조각은 앱 로그의 상태 전이와 화면이 바뀐 프레임을 겹쳐 시작 시각을 정한다(`compose_demo.py` 머리말). 맞춘 값과 확인 값은 `recordings/<폴더>/sync.json`.
- `recordings/`는 저장소에 넣지 않는다.

## 손으로 찍을 때

OBS Studio(화면 캡처 PipeWire + 오디오 출력 캡처)로 에뮬레이터 창과 콘솔 브라우저 탭을 한 화면에 놓고 [시연순서.md](시연순서.md)의 표대로 누른다. 또는 GNOME 화면 녹화(소리 없음) + `parecord --monitor-stream=<qemu 번호> recordings/audio.wav`를 따로 받아 ffmpeg로 합친다(재생을 누른 프레임과 소리가 시작된 때의 차이를 `-itsoffset`으로 맞춤).
